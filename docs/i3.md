# i3 session

`dotfiles.i3.enable` writes the session to `~/.hm-xsession`, but Home Manager cannot add an entry to the login screen.
The system layer supplies that entry, once per machine.

## NixOS (hades)

In the nixos repo's machine configuration:

```nix
services.displayManager.defaultSession = "gnome";
services.displayManager.sessionPackages = [
  (pkgs.writeTextDir "share/xsessions/i3-hm.desktop" ''
    [Desktop Entry]
    Name=i3 (Home Manager)
    Exec=$HOME/.hm-xsession
    Type=Application
    DesktopNames=i3
  '' // { providedSessions = [ "i3-hm" ]; })
];
```

`services.xserver.enable` has to be on, which it is on hades.
GDM runs the `Exec` line through the NixOS X session wrapper (`/etc/gdm/Xsession`), which `eval`s it, so `$HOME` expands at login.
`defaultSession` keeps autologin on GNOME.
Without it, GDM autologs into whichever session was picked last, so one i3 login would make the next boot land in i3.
To use i3, log out and pick "i3 (Home Manager)" from the gear menu on the GDM password prompt.

## Other distributions (darter)

Place this file as root at `/usr/share/xsessions/i3-hm.desktop`:

```ini
[Desktop Entry]
Name=i3 (Home Manager)
Exec=/bin/sh -c "exec $HOME/.hm-xsession"
Type=Application
DesktopNames=i3
```

GDM lists it on the next login.

## Switching

Both sessions stay installed; the login screen picks one.
Nothing from the i3 session starts inside GNOME, because its units hang off `hm-graphical-session.target`, which only `~/.hm-xsession` starts.
Check from a GNOME session with `systemctl --user is-active picom xss-lock`, which should print `inactive` twice.

In i3, Super+/ lists the key bindings.
